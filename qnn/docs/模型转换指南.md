# 模型转换指南：Paddle → ONNX → QNN 全链路

## 概述

PaddleOCR-VL 的文档解析 pipeline 包含两个关键子模型：

| 子模型 | 架构 | 参数量 | 功能 |
|--------|------|--------|------|
| 布局检测 | PP-StructureV3 (RT-DETR) | ~20M | 检测文本/表格/公式/图表区域 |
| VL 识别 | PP-DocBee2-3B (Qwen2.5-VL) | ~3B | 视觉语言理解，输出结构化文本 |

VL 识别模型进一步拆分为：
- **视觉编码器** (SigLip-400M): 图像特征提取
- **文本解码器** (Qwen2.5-3B): 自回归文本生成，拆分为 prefill 和 decode 两个子图

## 转换链路

```
Paddle 模型 (.pdmodel + .pdiparams)
    ↓  Paddle2ONNX
ONNX 模型 (.onnx)
    ↓  qnn-onnx-converter
QNN 模型 (.cpp + .bin)
    ↓  qnn-model-lib-generator
QNN 共享库 (.so)
    ↓  qnn-context-binary-generator
HTP 上下文二进制 (_ctx.bin)  ← 最终推理使用
```

## Step 1: Paddle → ONNX

### 1.1 布局检测模型

```bash
# 下载模型
paddleocr model -t structure -d PP-StructureV3
# 模型位于 ~/.paddleocr/models/PP-StructureV3/

# 导出 ONNX
python scripts/export_paddle_to_onnx.py \
    --model_type layout \
    --model_dir ~/.paddleocr/models/PP-StructureV3 \
    --output_dir ./models/onnx \
    --opset 14
```

输出：`./models/onnx/layout_detection.onnx`

**关键参数**：
- `opset_version=14`: QNN 对 opset 14 支持最好
- `auto_update_opset=True`: 自动提升不兼容算子的 opset

### 1.2 VL 识别模型

VL 模型的转换有两条路径：

**路径 A：Paddle2ONNX 直接导出（优先）**

```bash
python scripts/export_paddle_to_onnx.py \
    --model_type vl \
    --model_dir ~/.paddleocr/models/PP-DocBee2-3B \
    --output_dir ./models/onnx
```

**路径 B：通过 HuggingFace + optimum 导出**

如果路径 A 遇到算子不支持的问题：

```bash
pip install optimum[exporters]

# 自动导出所有子组件
optimum-cli export onnx \
    --model PaddlePaddle/PP-DocBee2-3B \
    --task image-text-to-text \
    ./models/onnx/vl/
```

输出文件：
- `vl_vision_encoder.onnx`
- `vl_text_decoder_prefill.onnx`
- `vl_text_decoder_decode.onnx`

### 1.3 ONNX 验证

## Step 2: ONNX → QNN

### 2.1 环境准备

```bash
# 设置 QNN SDK 环境
export QNN_SDK_ROOT=/path/to/qairt/<version>
source $QNN_SDK_ROOT/bin/envsetup.sh

# 验证工具可用
qnn-onnx-converter --help
qnn-model-lib-generator --help
qnn-context-binary-generator --help
```

### 2.2 转换命令

**全链路自动转换**：

```bash
python scripts/convert_onnx_to_qnn.py \
    --input_dir ./models/onnx \
    --output_dir ./models/qnn \
    --backend htp
```

**手动逐步转换**（以布局检测为例）：

```bash
# Step 2a: ONNX → QNN C++
qnn-onnx-converter \
    --input_network ./models/onnx/layout_detection.onnx \
    --output_path ./models/qnn/models/layout_detection.cpp \
    --input_layout NCHW NHWC

# Step 2b: 编译共享库
qnn-model-lib-generator \
    -c ./models/qnn/models/layout_detection.cpp \
    -b ./models/qnn/models/layout_detection.bin \
    -o ./models/qnn/libs \
    -t x86_64-linux-clang

# Step 2c: 生成 HTP 上下文二进制
qnn-context-binary-generator \
    --model ./models/qnn/libs/x86_64-linux-clang/liblayout_detection.so \
    --backend $QNN_SDK_ROOT/lib/x86_64-linux-clang/libQnnHtp.so \
    --binary_file ./models/qnn/context_binaries/layout_detection_ctx.bin
```

### 2.3 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| `Unsupported op: XXX` | QNN 不支持该 ONNX 算子 | 升级 QNN SDK / 使用 `--custom_op_config` 注册自定义算子 |
| `Input layout mismatch` | HTP 要求 NHWC 布局 | 添加 `--input_layout NCHW NHWC` |
| `Memory allocation failed` | 3B 模型太大 | 拆分子图 / 使用更大内存的机器 |
| `Quantization failed` | 校准数据不足 | 增加校准样本数到 100+ |

## Step 3: 量化

### 3.1 量化策略

| 子模型 | 推荐精度 | 理由 |
|--------|---------|------|
| 布局检测 (RT-DETR) | INT8 | CNN 结构对 INT8 量化友好，精度损失极小 |
| 视觉编码器 (SigLip) | FP16 | ViT 对低精度量化敏感 |
| 文本解码器 (Qwen2.5) | FP16 | LLM 对量化最敏感，FP16 保精度 |

### 3.2 生成校准数据

```bash
# 准备 50-100 张代表性文档图片到 data/calibration_images/
python scripts/quantize_models.py calibrate \
    --image_dir ./data/calibration_images \
    --output_dir ./data/calibration \
    --num_samples 100
```

### 3.3 执行量化

```bash
# 自动量化（使用推荐策略）
python scripts/quantize_models.py quantize --model all

# 或手动指定精度
python scripts/quantize_models.py quantize --model layout_detection --precision int8
python scripts/quantize_models.py quantize --model vl_vision_encoder --precision fp16
```

### 3.4 量化验证

量化后务必运行精度评测：

```bash
python scripts/evaluate_accuracy.py report --results_dir ./results
```

如果精度损失 > 5%，调优建议：
1. 将 INT8 层切换为 FP16
2. 增加校准数据多样性
3. 使用混合精度（`--act_bw 16 --weight_bw 8`）
