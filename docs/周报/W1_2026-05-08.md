### 1.3 Phase 2：文档解析与切片模块（提前启动）

| 模块 | 文件 | 关键能力 |
|------|------|----------|
| PDF 预处理 | `openvino/src/pdf_preprocessor.py` | pdfplumber 文字层抽取 → 命中率判断（≥90% 走文字层）；不命中页用 pypdfium2 渲染（自带二进制，免装 poppler）|
| 文档解析 | `openvino/src/doc_parser.py` | 复用文字层 / 调用 PaddleOCR-VL OpenVINO 全图 prompt；输出结构化 Markdown，按页携带 `source` 元信息 |
| 表格感知切片 | `openvino/src/chunker.py` | Markdown 表格识别（`\|...\|` + 分隔符）→ 表头 + 单行 chunk；非表格按段落切 200~500 字符，超长保留 50 字符 overlap |
| 端到端管线 | `openvino/src/pipeline.py` + `scripts/run_phase2_pipeline.py` | PDF → 预处理 → 解析 → 切片 → JSONL，带元数据 `{doc_name, page, section_title, kind}` |
| 测试数据 | `openvino/data/test_documents/` | 合成 3 份 PDF：`text_pdf.pdf`（含文字层）、`scanned.pdf`（图像化扫描件）、`spec_with_tables.pdf`（含表格规格书）|

### 1.4 关键链路本地验证

- `chunker.chunk_page` 在合成 markdown 上输出 7 个 chunk：3 个文本 chunk（标题 + 段落）+ 1 个表头 chunk + 2 个表格行 chunk（每行携带表头 + 分隔符）+ 1 个尾部章节 chunk，元数据完整
- `pdf_preprocessor.preprocess_pdf` 对 3 份测试 PDF 的判定：
  - `text_pdf.pdf`：mode=mixed（页 1 文字层命中，页 2 字数过少自动转 OCR）
  - `scanned.pdf`：mode=ocr（无文字层，2 页全部走 OCR 路径）
  - `spec_with_tables.pdf`：mode=text（文字层命中走快速路径）

## 3. 遇到的问题与风险

| 问题 | 影响 | 当前应对 |
|------|------|----------|
| PaddleOCR-VL 在官方 optimum 导出器中暂未原生支持 | 无法直接用 `optimum-cli export openvino` 一键转换 | 改用社区 `paddleocr_vl_openvino` wheel 或下载 ModelScope 预转 IR |
| ModelScope 预转 IR 采用拆分布局（`llm_stateful_int4`、`vision_int8`、`vision_mlp` 等），与 `openvino_genai.VLMPipeline` 默认期望文件名不兼容 | 直接用 `VLMPipeline(ir_dir)` 加载会失败 | 在 `src/inference.py` 增加适配层，自动识别两种 IR 布局 |
| 真实业务 PDF 样本暂未到位 | Phase 2 验证目前用合成样本，覆盖度不足 | 下周补齐 3 份真实文档（说明书、规格书、扫描件）|
