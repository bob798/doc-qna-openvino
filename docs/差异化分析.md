# 方案差异化分析：与现有 OpenVINO notebooks 的区别

---

## 结论：不重复，差异点在解析层

现有 RAG notebook（Create a RAG system using OpenVINO and LangChain）说"支持 PDF"，实际是指**机器生成的、文字层可提取的 PDF**。遇到以下情况会失败：

- 扫描版产品手册
- 含嵌入式图片的技术文档
- 带复杂表格的规格书
- 含公式的说明书

本方案的创新点刚好在这一层：用 PaddleOCR-VL 替换掉 Tesseract，让 RAG 能消化真实企业里格式复杂的产品文档。

---

## 核心差异对比

| 维度 | 现有 RAG notebook | 本方案 |
|------|-----------------|---------|
| 文档解析工具 | LangChain Unstructured + Tesseract OCR | **PaddleOCR-VL** |
| 表格处理 | 提取为 HTML，能力有限 | 原生理解表格结构 |
| 公式/图表 | 不支持 | 支持 |
| 目标文档类型 | 机器可读 PDF、纯文本 | 扫描件、图文混排、产品手册 |
| 多语言 | 依赖 Tesseract，有限 | 109种语言 |
| OCR 质量 | 一般 | SOTA（PaddleOCR-VL） |

---

## RFC 关键句

> 现有 OpenVINO RAG notebooks 采用 LangChain Unstructured + Tesseract 进行文档解析，难以处理扫描件、图文混排及含公式/图表的产品手册。本项目以 PaddleOCR-VL 替换解析层，使 RAG 系统具备处理真实企业级复杂文档的能力，填补现有方案在非结构化文档入库环节的空白。

---

## 方案定位

**核心主张**：产品文档零人工自动入库，解决企业知识库冷启动问题

**一句话描述**：
> 基于 PaddleOCR-VL + OpenVINO 的产品文档智能入库与客服问答系统——让任意格式的产品手册5分钟内变成可问答的知识库。

**系统架构**：

```
【上游】文档自动入库
    原始产品手册（PDF/扫描件/图文混排）
        ↓
    PaddleOCR-VL 解析（文字+表格+公式+图表）
        ↓
    结构化切片 + 向量化入库

【下游】客服问答
    用户提问
        ↓
    检索相关文档片段
        ↓
    OpenVINO 加速 LLM 推理
        ↓
    回答客户问题
```
