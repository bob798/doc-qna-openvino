## Phase 1: 环境搭建与模型验证 (Week 1)

**目标**：跑通 PaddleOCR-VL + OpenVINO 推理，获取第一组实测数据

### 环境准备

- [ ] 安装 OpenVINO Runtime + OpenVINO GenAI
- [ ] 安装依赖：`pdf2image`、`pdfplumber`、`chromadb`、`Pillow`
- [ ] 下载 PaddleOCR-VL 模型（HuggingFace）
- [ ] 将模型转换为 OpenVINO IR 格式（参考 [PaddleOCR-VL Notebook](https://github.com/openvinotoolkit/openvino_notebooks/tree/latest/notebooks/paddleocr_vl)）
- [ ] 记录环境信息：OS / CPU 型号 / 内存 / OpenVINO 版本

### Benchmark 1：推理速度

- [ ] 准备 10 张测试图片（分类：纯文字 ×3、表格 ×3、公式 ×2、图文混排 ×2）
- [ ] PyTorch 推理：逐张跑，记录每张耗时
- [ ] OpenVINO 推理：逐张跑，记录每张耗时
- [ ] 计算加速比，**用实测数据替换方案中"≥ 2x"预估**

### Benchmark 2：解析质量对比

- [ ] 同一组 10 张图片，分别用 Tesseract 和 PaddleOCR-VL 解析
- [ ] 人工评估：逐张对比识别准确率（特别关注表格结构、公式、多语言）
- [ ] 截图保存对比结果（后续放入 Notebook 演示）

### 验证标准

- [x] 能在 Notebook 中跑通 PaddleOCR-VL OpenVINO 推理
- [ ] 有推理速度实测数据表
- [ ] 有 Tesseract vs PaddleOCR-VL 解析质量对比截图

## Phase 2: 文档解析与切片模块 (Week 2)

**目标**：完成从原始文档到可检索 chunk 的完整管线

### PDF 预处理

- [ ] 实现 PDF 可读性判断
  - 用 `pdfplumber` 尝试提取文字
  - 提取到足够文字 → 直接用文字层
  - 提取失败或文字过少 → 走 PaddleOCR-VL OCR 路径
- [ ] PDF 转图片：`pdf2image`，按页转换

### PaddleOCR-VL 解析

- [ ] 逐页调用模型，输出结构化 Markdown
- [ ] 处理多页文档：合并各页结果，保留页码信息

### 表格感知切片

- [ ] 解析 Markdown 中的表格块（检测 `|` 分隔符模式）
- [ ] 表格切片规则：
  - 每行数据 + 表头 → 组成一个 chunk
  - 示例：`| 型号 | 功率 | 温度 |\n| A100 | 300W | -20~70℃ |` → 一个 chunk
- [ ] 非表格切片规则：
  - 按语义段落切分（以标题、空行为边界）
  - chunk 大小控制在 300-500 字符
  - 过长段落做二次切分，保留 50 字符重叠
- [ ] 元数据附加：每个 chunk 携带 `{doc_name, page, section_title}`

### 验证标准

- [ ] 准备 3 份测试文档：纯文本 PDF、扫描件、含表格规格书
- [ ] 跑全流程，输出 chunk 列表
- [ ] 人工检查：表格 chunk 是否完整、段落切分是否合理、元数据是否正确

## Phase 3: RAG 问答链路 (Week 3)

**目标**：完成检索 + 生成全链路，能输入问题输出带引用的回答

### Embedding + 入库

- [ ] 下载 BGE-small 模型，转换为 OpenVINO 格式
- [ ] 实现 chunk 批量 embedding
- [ ] 存入 ChromaDB（带元数据）

### 检索模块

- [ ] 实现 query embedding → ChromaDB Top-K 检索（K=5）
- [ ] 返回检索结果 + 相似度分数 + 元数据

### LLM 生成

- [ ] 下载 Qwen2.5-7B，INT4 量化 + OpenVINO GenAI 推理
- [ ] Prompt 模板设计：
  ```
  你是一个产品客服助手。根据以下参考资料回答用户问题。
  如果资料中没有相关信息，请明确告知。

  参考资料：
  {retrieved_chunks}

  来源：{chunk_metadata}

  用户问题：{query}
  ```
- [ ] 输出格式：回答文本 + 来源引用（文档名 + 页码）

### Benchmark 3：端到端延迟

- [ ] 准备 10 个测试问题（覆盖：参数查询、流程说明、对比类问题）
- [ ] 逐环节计时：

  | ChromaDB 检索 | ? |
  | LLM 首 token | ? |
  | LLM 生成完成 | ? |
  | **端到端总计** | ? |
- [ ] **用实测数据替换方案中"< 15s"预估**

### 验证标准
