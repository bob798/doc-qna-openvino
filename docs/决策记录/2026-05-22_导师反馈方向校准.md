## 三、决策

### 主线 vs 加分项 重排

| 优先级 | 内容 | 状态变化 |
|--------|------|----------|
| **P0 主线** | Phase 3.1 Embedding + ChromaDB | 维持 |
| **P0 主线** | Phase 3.2 LLM + 带引用回答 | 维持 |
| **P0 主线** | Phase 3.3 端到端 `run_qa.py`（1~2 PDF + 3~5 题） | 维持，但**只跑 3~5 题，不是 5~10** |
| **P0 主线** | README + 复现物料 | 从 W7（最后一周）**提前到端到端跑通当晚并行启动** |
| **P0 主线** | NPU 限制说明（一句话） | 替代原"NPU benchmark 全链路" |
| **P1 必做** | 业务问题集精简（3~5 题，Demo 主证据） | 从"扩 30~50 题"**降级到精挑 3~5 题** |
| **P1 必做** | Tesseract vs PaddleOCR-VL 少量对比（2~3 页） | 替代"OmniDocBench 子集 20 张完整跑" |
| **P2 加分** | NPU 进取路径（LLM/Embedding 切 NPU） | W4 时间允许时做，**时间不够直接砍** |
| **P3 加分** | OmniDocBench 完整 / RAGAS / 业务题扩 30~50 / Gradio UI | 6/2 前主线没稳就**完全砍掉** |

### NPU 路径决策

- **W3 主线**：保守 — 一句话限制说明（"当前 IR 含 PP-DocLayoutV3 算子，NPU 暂不支持完整 OCR 链路；主线用 CPU/GPU/AUTO"）。
- **W4 加分（时间允许时）**：进取 — 把 Qwen3-1.7B-int4 LLM 或 BGE Embedding 切到 NPU 跑，讲"OCR-GPU / LLM-NPU / 检索-CPU"AI PC 全家桶叙事。
- **绝对不做**：硬试 PP-DocLayoutV3 在 NPU 上跑 OCR 链路。
