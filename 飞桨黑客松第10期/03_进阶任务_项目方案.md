# 进阶任务 #13 · 初步方案说明

> 基于 PaddleOCR-VL + OpenVINO 的产品文档智能入库与客服问答系统
> 
> 让任意格式的产品手册 5 分钟内变成可问答的知识库

---

## 一、应用场景

**目标用户**：拥有大量产品手册/技术文档的企业客服团队

**核心痛点**：
- 企业产品文档格式复杂（扫描件 PDF、图文混排、含表格/公式的规格书），传统 OCR + RAG 方案无法正确解析
- 人工整理文档入库成本高、周期长，知识库"冷启动"困难
- 客服人员需反复翻阅手册回答重复性问题，效率低下

**典型场景举例**：
- 某硬件厂商有 200+ 份产品规格书（PDF 扫描件），需要快速建立客服知识库
- 客户询问"XX 型号的工作温度范围是多少？"——答案藏在某份规格书的表格第 3 行

---

## 二、与现有 OpenVINO Notebooks 的差异

> **先看差异，再看方案——这是本方案存在的理由。**

现有 OpenVINO 生态中有两类相关 Notebook：
- **PaddleOCR-VL Notebook**：单模型推理演示（输入图片 → 输出识别结果），无 RAG 链路
- **RAG Notebook**（LangChain + OpenVINO）：用 Unstructured + Tesseract 解析文档，只能处理机器可读 PDF

**本方案的组合创新**：将 PaddleOCR-VL 的文档理解能力嵌入 RAG 链路，填补"复杂文档 → 可问答知识库"这一环节的空白。

| 维度 | 现有 RAG Notebook | 本方案 |
|------|-------------------|--------|
| 文档解析 | Unstructured + Tesseract | **PaddleOCR-VL**（OpenVINO 加速） |
| 可处理文档 | 机器可读 PDF、纯文本 | 扫描件、图文混排、含表格/公式的手册 |
| 表格处理 | 提取为 HTML，能力有限 | 原生理解表格结构，保留行列语义 |
| 切片策略 | 固定长度切片 | 表格行+表头为 chunk，段落按语义切 |
| 端到端场景 | 通用问答 | **产品文档零人工入库 → 客服问答** 完整链路 |

---

## 三、技术思路

采用 **上游入库 + 下游问答** 两段式架构，纯 Python 实现，无框架依赖：

### 上游：文档智能解析与入库

```
原始产品文档（PDF / 扫描件 / 图片）
        ↓
   PaddleOCR-VL（OpenVINO 加速）
   → 识别文字、表格、公式、图表
   → 输出结构化 Markdown
        ↓
   智能切片（表格感知 + 语义段落）
        ↓
   Embedding 向量化 → 存入向量数据库
```

**关键设计**：

1. **表格感知切片**：
   - 表格内容：每行数据 + 表头组成一个 chunk，保证检索到任意一行都能还原完整语义
   - 非表格内容：按语义段落切分，chunk 大小 300-500 字符
   - 每个 chunk 携带元数据（来源文档名、页码、章节标题），支持答案溯源

2. **多格式适配**：PDF 先判断是否为机器可读（尝试直接提取文字），不可读时走 PaddleOCR-VL 路径

### 下游：检索增强问答

```
用户提问
    ↓
Query Embedding → 向量检索 Top-K 相关片段
    ↓
Prompt 拼装（系统指令 + 检索片段 + 用户问题）
    ↓
LLM 生成回答（OpenVINO 加速推理）
    ↓
返回答案 + 来源引用（文档名 + 页码）
```

## 四、工具框架

| 组件 | 选型 | 说明 |
|------|------|------|
| 文档解析 | **PaddleOCR-VL** (0.9B) | 核心差异化组件，109 种语言，表格/公式/图表原生理解 |
| 推理加速 | **OpenVINO** | 对 PaddleOCR-VL、Embedding、LLM 三个模型统一加速 |
| 向量数据库 | **ChromaDB** | 轻量级，Notebook 内直接运行，无外部服务依赖 |
| Embedding | **BGE-small** (OpenVINO 加速) | 轻量高效，支持中英文 |
| LLM | **Qwen2.5-7B** (OpenVINO INT4 量化) | 本地 CPU 运行，无需 API |
| 编排 | **纯 Python** | 全链路代码透明，每步可审 |
| 前端展示 | **Gradio**（可选） | 如时间充裕加入交互界面 |

## 五、预期效果

### 功能效果
1. **5 分钟入库**：上传任意格式产品手册，自动完成 解析 → 切片 → 向量化 全流程
2. **精准表格问答**：能正确回答"XX 型号参数是多少"这类需要定位表格单元格的问题
3. **来源可溯**：每个回答附带引用来源（文档名 + 页码），支持人工核验

### 性能指标（预期）

| 指标 | 目标 |
|------|------|
| PaddleOCR-VL 推理（OpenVINO vs PyTorch） | 加速比 ≥ 2x |
| LLM 首 token 延迟（INT4 量化，Intel CPU） | < 2s |
| 端到端问答响应（CPU） | < 15s |
| 扫描件文字识别准确率 | ≥ 95%（中英文混合场景） |

*以上为基于公开基准数据的预估值，最终以实测为准。*

### 演示 Demo 规划

**核心演示：Tesseract vs PaddleOCR-VL 对比**（放在 Notebook 最前面，先建立说服力）

1. 选取一份**表格密集的扫描件**产品规格书
2. 分别用 Tesseract 和 PaddleOCR-VL 解析，并排展示解析结果
3. 用同一个问题（如"XX 型号的额定功率是多少？"）分别在两个解析结果建的知识库上检索
4. 对比回答质量：Tesseract 方案答错或答不出 vs PaddleOCR-VL 方案精准命中

**完整流程演示**：
- 准备 3-5 份真实产品手册（纯文本 PDF、扫描件、含表格规格书）
- 展示从上传到可问答的端到端流程
