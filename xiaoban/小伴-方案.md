## 一、项目定位

**一句话描述**：一个放在书桌上、能看到你、听懂你、记得住你的学习机器人。

**核心命题**：学习是一个长期过程，但现有的 AI 学习工具都是"一次性"的——每次交互从零开始，不认识用户，关掉就消失。小伴 要做的是一个**有长期记忆、能自主规划教学、具备物理存在感的实体学习机器人**。

**四层能力缺一不可**：

| 能力 | 解决的问题 | 实现方式 |
|------|-----------|---------|
| Agent 架构 | 理解复杂指令，不只是一问一答 | 文心大模型 × 3 次调用（意图→规划→执行） |
| 长期记忆 | 跨会话认识用户，越用越懂你 | 用户画像 + 生活事实 + 知识卡片 |
| 科学调度 | 自主决定教什么、什么时候教 | FSRS 间隔重复算法 |
| 具身交互 | 物理存在感，让陪伴变得真实 | RDK X3：摄像头感知 + 舵机反馈 + 端侧推理 |

## 二、为什么是实体机器人

这个问题必须在方案开头回答，因为它决定了整个项目的设计方向。

**软件能做到的**：理解语音、生成回复、记住用户、规划教学。这些能力一个 App 就能实现。

**软件做不到的**：

| 场景 | App 的表现 | 实体机器人的表现 |
|------|-----------|----------------|
| 用户坐到书桌前 | 什么也不发生，等用户打开 App | 检测到用户，主动说"今天有 3 个知识点到期了" |
| 用户学到一半走神 | 不知道，继续输出 | 摄像头检测到走神，切换话题或发起互动 |
| 用户答对一道难题 | 屏幕弹个动画 | 点头 + LED 变绿 + 语音鼓励（三重正反馈） |
| 用户担心隐私 | 语音上传云端处理 | 端侧 BPU 推理，语音不出设备 |
| 用户关掉设备 | App 消失，陪伴关系中断 | 机器人始终在桌上，随时可交互 |

**实体机器人的核心价值不是"跑 AI 的硬件"，而是"物理存在感带来的陪伴关系"。** 这是 App/网页永远无法替代的。

## 三、场景描述

一个放在书桌上的学习机器人。

早上你坐到桌前，它的 LED 亮起，说："早上好，昨天的 go/went 你掌握得不错，今天我们试试 make 和 do 的区别？"

你说"好的，开始吧"。它不需要你选课程、翻菜单——它记得你是产品经理、英语 B1 水平、上周和老板开了季度 review、过去时是你的薄弱点。它根据这些信息，自己规划了今天的教学内容。

你说了一句 "Yesterday I make a presentation"，它没有打断你说"错了"，而是自然回复："Oh nice — did you make the slides yourself, or did someone do them for you?" 在回复中示范了正确的 make/do 用法。

你皱了皱眉，摄像头捕捉到困惑表情，它放慢节奏："Let me explain — we usually say 'make a presentation' but 'do the homework'. It's about creating something new vs completing a task."

练习结束，它点了点头，LED 变绿："Great session today. 你的 make/do 正确率从 60% 提升到了 85%。"

**这就是"陪伴式学习"的完整体验——感知你的状态、理解你的意图、规划教学内容、用物理动作给予反馈。**

## 四、系统架构

### 整体架构（阶段 1 + 阶段 2）

```
┌─ 感知层 ─────────────────────────────────────────────────┐
│                                                            │
│  阶段 1（软件验证）         阶段 2（RDK X3 实体）           │
│  ┌──────────────┐         ┌───────────────────────┐       │
│  │ 麦克风 → 百度 │         │ 麦克风阵列 → hobot_asr │       │
│  │ 短语音识别    │         │         (BPU 端侧)    │       │
│  └──────────────┘         ├───────────────────────┤       │
│                            │ MIPI 摄像头 → 表情识别  │       │
│                            │         (BPU 端侧)    │       │
│                            ├───────────────────────┤       │
│                            │ 接近传感器 → 用户在场检测│       │
│                            └───────────────────────┘       │
└────────────────────────────────────────────────────────────┘
                            ↓ 用户文本 + 感知信号
┌─ 决策层（Agent 大脑）──────────────────────────────────────┐
│                                                            │
│  文心大模型 API × 3 次调用：                                │
│                                                            │
│  用户输入 → ① 意图理解（ERNIE-4.0-Turbo, t=0.1）          │
│               → 判断：practice / review / summary / chat   │
│                                                            │
│           → ② 任务规划（ERNIE-4.0-Turbo, t=0.3）          │
│               → 结合 用户画像 + FSRS 到期卡片 + 感知信号    │
│               → 生成教学步骤序列                            │
│                                                            │
│           → ③ 对话执行（ERNIE-4.0-8K, t=0.7）             │
│               → 注入记忆 + 教学计划 → 生成自然对话回复       │
│                                                            │
│  ┌─ 记忆系统（本地 SQLite）──────────────────────┐         │
│  │ user_profile:  职业 / 水平 / 目标             │         │
│  │ user_facts:    近期生活事件（每轮提取 2-3 条） │         │
│  │ grammar_cards: 知识卡片（FSRS 6 算法调度）    │         │
│  └───────────────────────────────────────────────┘         │
└────────────────────────────────────────────────────────────┘
                            ↓ 回复文本 + 执行指令
┌─ 执行层 ─────────────────────────────────────────────────┐
│                                                            │
│  阶段 1（软件验证）         阶段 2（RDK X3 实体）           │
│  ┌──────────────┐         ┌───────────────────────┐       │
│  │ 百度语音合成  │         │ hobot_tts (BPU 端侧)  │       │
│  │ → 浏览器播放  │         │ → 扬声器播放           │       │
│  ├──────────────┤         ├───────────────────────┤       │
│  │ 前端 UI 渲染  │         │ 舵机：点头/摇头/举手    │       │
│  │ 学习卡片/报告 │         │ LED：绿(正确)/黄(提示) │       │
│  └──────────────┘         │ 屏幕：学习数据仪表盘    │       │
│                            └───────────────────────┘       │
└────────────────────────────────────────────────────────────┘
```

### 关键设计：为什么文心 API 拆成 3 次调用

```
普通聊天机器人：  用户说话 → LLM → 回复（一步到位，黑箱不可控）

小伴 Agent： 用户说话 → ① 意图理解 → ② 任务规划 → ③ 对话生成
                              ↑              ↑              ↑
                         temperature=0.1  temperature=0.3  temperature=0.7
                         （精确分类）      （结构化推理）    （自然对话）
```

- **可观测**：每步输入输出可审查，便于调试
- **可控制**：分类用低 temperature 保证准确，对话用高 temperature 保证自然
- **可替换**：任意一层可独立升级模型或替换为规则引擎

## 五、文心大模型 API 集成

### 调用点总览

| 调用点 | 角色 | 输入 | 输出 | 模型 | temperature |
|--------|------|------|------|------|------------|
| ① | 意图分类器 | 用户文本 + 上下文 | `{intent, params, confidence}` | ERNIE-4.0-Turbo | 0.1 |
| ② | 教学规划器 | 意图 + 画像 + FSRS 卡片 + 感知信号 | 教学步骤序列 JSON | ERNIE-4.0-Turbo | 0.3 |
| ③ | 对话教练 | 教学计划 + 记忆 + 对话历史 | 自然语言回复 | ERNIE-4.0-8K | 0.7 |

### 接入方式

通过千帆 v2 API（OpenAI 兼容格式），使用 IAM 安全认证（Bearer token），不再使用旧版 access_token 流程。

### 容错策略

```
文心 API 正常 → 使用 ERNIE-4.0
  ↓ 超时（>8s）或报错
自动重试 1 次（指数退避）
  ↓ 仍然失败
降级到 ERNIE-3.5-Turbo（更低延迟、更高可用性）
  ↓ 千帆平台整体不可用
纯本地模式 → FSRS 卡片列表 + 百度端侧 TTS 提示（阶段 2 可用）
```

全链路基于百度生态，LLM / STT / TTS 统一使用百度智能云服务。

## 六、RDK X3 硬件方案

### RDK X3 硬件规格与能力适配

RDK X3 是本次活动指定的硬件平台。以下是其关键规格及对 小伴 各层能力的支撑：

| 硬件规格 | 参数 | 支撑的能力层 |
|---------|------|-----------|
| CPU | 4 核 Cortex-A53 @ 1.5GHz | 决策层：运行 Agent 服务、ROS 2 节点编排 |
| BPU | 5 TOPS（Bernoulli 架构） | 感知层：端侧 STT/TTS/表情识别推理 |
| 摄像头 | 2× MIPI CSI-2 | 感知层：用户表情捕捉、教材内容识别 |
| GPIO | 40-pin（兼容树莓派） | 执行层：PWM 驱动舵机、GPIO 控制 LED |
| 音频 | USB 麦克风 + 3.5mm 扬声器 | 感知层 + 执行层：语音输入输出 |
| 网络 | Wi-Fi 5GHz + 千兆以太网 | 决策层：文心 API 云端调用 |
| 操作系统 | Ubuntu 20.04/22.04 | 全局：Python/FastAPI/ROS 2 原生支持 |

### RDK X3 解锁的三个能力

**1. 具身感知：看到用户状态**

摄像头 + BPU 实时推理：
- 用户皱眉/困惑 → 自动放慢节奏、补充解释
- 用户走神/分心 → 切换话题或发起互动
- 用户手持教材 → 进入"教材辅导"模式
- 用户坐下 → 主动打招呼并提醒今日学习计划

**2. 具身反馈：物理动作强化记忆**

教育心理学研究表明多感官反馈比纯文字/语音更能加深记忆：
- 答对 → 舵机点头 + LED 变绿 + 语音鼓励（三重正反馈）
- 答错 → 舵机轻摇头 + LED 变黄 + 语音温和引导
- 完成复习 → 舵机"举手"庆祝

**3. 端侧推理：隐私与低延迟**

利用 D-Robotics 提供的 ROS 2 节点：
- `hobot_asr`：端侧中英文语音识别，延迟 ~100ms（云端 ~500ms）
- `hobot_tts`：端侧语音合成，断网仍可用
- 语音数据全程本地处理，不上传云端

### 阶段 1 → 阶段 2 的演进路径

```
阶段 1（软件验证）                阶段 2（RDK X3 实体）
──────────────                  ──────────────────
验证 Agent 大脑 ───────────────► 给大脑装上身体

感知：百度短语音识别 ──────────► 端侧 hobot_asr + 摄像头
决策：文心 API + FSRS ─────────► 不变（决策层设计与硬件无关）
执行：百度语音合成 + UI ────────► 端侧 hobot_tts + 舵机 + LED
通信：HTTP ────────────────────► ROS 2 Topic（TogetheROS.Bot）
```

**决策层的设计不依赖硬件**——这是分阶段验证能成立的前提。Agent 链路（文心 API + 记忆 + FSRS）在阶段 1 用浏览器验证，在阶段 2 原封不动搬到 RDK X3。变化的只有感知层和执行层的物理接口。

## 七、技术栈

### 阶段 1（软件验证）——全链路百度生态

| 组件 | 选型 | 说明 |
|------|------|------|
| LLM | **文心大模型 API**（ERNIE-4.0） | Agent 大脑，3 次调用 |
| STT | **百度短语音识别**（极速版） | 感知层：语音→文本，支持中英文（`dev_pid` 切换） |
| TTS | **百度语音合成**（在线） | 执行层：文本→语音，支持多音色/语速 |
| 记忆调度 | **FSRS 6**（py-fsrs） | 科学调度引擎 |
| 数据库 | SQLite + aiosqlite | 记忆持久化 |
| 后端 | FastAPI（Python） | 异步 API |
| 前端 | HTML + JS（轻量 Web） | 阶段 1 仿真交互终端，阶段 2 由硬件交互替代 |
| 部署 | Docker Compose | 一键启动 |

> 阶段 1 前端仅作为 Agent 链路的验证界面，不是产品终态。阶段 2 用户交互入口切换为麦克风/摄像头/舵机等物理设备，Web 界面仅保留调试和数据查看功能。

### 阶段 2 新增（RDK X3 硬件）

| 组件 | 选型 | 说明 |
|------|------|------|
| 开发板 | **RDK X3**（4GB） | 主控：CPU + 5T BPU |
| 端侧 STT | hobot_asr（ROS 2 节点） | BPU 加速，替换云端百度语音识别 |
| 端侧 TTS | hobot_tts（ROS 2 节点） | BPU 加速，替换云端百度语音合成 |
| 视觉感知 | MIPI 摄像头 + BPU 推理 | 表情识别、用户在场检测 |
| 物理执行 | SG90 舵机 × 2 + WS2812 LED | 点头/摇头 + 状态指示 |
| 中间件 | TogetheROS.Bot（ROS 2） | 节点编排与通信 |

## 九、失败场景处理

| 异常场景 | 处理策略 | 用户感知 |
|---------|---------|---------|
| STT 识别失败 | 提示重试 + 提供文本输入 | "没听清，请再说一次或打字告诉我" |
| 文心 API 超时（>8s） | 重试 1 次，仍失败则降级到 ERNIE-3.5-Turbo | 用户无感，日志记录 |
| 千帆平台不可用 | 纯本地：FSRS 卡片 + 百度端侧 TTS | "AI 暂时离线，先看今天的复习卡片" |
| 意图置信度低（<0.5） | 进入自由聊天模式 | 机器人正常对话，不执行错误操作 |
| 摄像头遮挡/光线不足 | 降级为纯语音模式 | 关闭表情感知，不影响核心教学 |
| 网络完全断开 | 端侧 STT/TTS + 本地 FSRS | 基本教学功能可用（阶段 2） |
